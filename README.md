# 鞋模具仓库系统

用于局域网内的鞋模具库存查询、自助领用归还和流转追溯。电脑运行服务并保存数据，人员使用本人账号和已授权的 Android 手机扫码办理作业，电脑网页用于查看库存、维护资料和处理异常。

系统按每个单模具记录编号、尺码、当前位置、状态和责任人；套号用于归组和查看齐套情况。扫描二维码只识别对象并加入清单，确认提交后才更新库存和历史记录，不会扫描一件就自动登记整套。

**当前阶段：开发与局域网测试，截至 2026-10-07。** 核心业务已实现，Android 调试 APK 已覆盖安装到 PMM110，关键业务和异常恢复已有自动化测试。真实领还、标签打印、备份恢复和跨电脑迁移仍需现场验收，当前不是正式发布版本。

## 使用方式

| 入口 | 当前用途 |
| --- | --- |
| 原生 Android App | 查询模具、连续扫码、批量领用和完好归还；支持手动输入、清单核对、草稿保存和原请求结果查询。 |
| 电脑网页 | 库位看板、模具和齐套查询、产线汇总、历史流水；办理领用、归还、移库、转线、异常处理及维护操作。 |
| 手机网页 | 登录、查询、扫码或照片识别，办理单件领用和完好归还；作为补充入口。 |

系统维护员管理基础资料、账号和设备授权，并处理盘点差异及异常；领用人员使用个人账号登记作业；只读账号用于查看库存和流水。日常作业通过局域网访问电脑服务，电脑需要保持开机；当前不支持离线自动登记库存。

## 已实现功能

- **库存与位置**：维护型号、模具套、单模具、库位和产线，查看当前位置、状态、责任人、齐套情况及流转历史。
- **流转登记**：领用、归还、移库、转线；电脑端支持逐件完好、待检或送修的混合归还，以及符合条件的补偿更正。
- **异常与盘点**：待检、维修、检验、报废、找回；按普通库位建立盘点任务、冻结流转、扫码核对、处理差异并留痕。
- **资料与标签**：CSV 模板、导入预览和整批确认、库存及流水导出；生成单模具和库位二维码，按套打印已有模具的标签，记录打印和补打请求。
- **权限与追溯**：账号角色、人员关联、设备登记授权与撤销、审计记录；删除产线时保留历史及尚未归还模具的位置。
- **提交保护**：服务端校验版本、状态、容量和盘点冻结；提交前保存原请求，断网或结果不确定时查询原单据并按原编号重试。Android 草稿绑定原服务器和账号，电脑清单保留扫码时的版本。

这些功能已接入代码和接口；实际二维码识别率、纸张打印效果及真实业务完整流程的验证状态见[项目进度](项目进度.md)。

## 手机与电脑如何配合

手机扫码或手输编号 → 核对目标位置和清单 → 通过电脑地址发送请求 → 后端校验权限与业务规则 → 在数据库事务中保存库存变化及流水 → 返回单据结果。

Android App 和网页都通过同一后端访问数据，手机不直接打开数据库。客户端保存的草稿和待确认请求用于恢复操作，库存以电脑数据库及服务端确认结果为准。

| 部分 | 技术与位置 |
| --- | --- |
| Android App | Kotlin、Compose、CameraX、ML Kit，源码在 `android/`。 |
| 电脑及手机网页 | React、TypeScript、Vite，源码在 `frontend/`。 |
| 电脑端服务 | Python、FastAPI、SQLAlchemy、Alembic，源码在 `backend/`。 |
| 当前活动数据库 | 项目内唯一的 SQLite 文件：`office-pilot-data/warehouse.sqlite3`。 |

## 开始测试

电脑需准备 Python 3.12 或 3.13、Node.js 和 npm；首次安装依赖需要相应网络或已准备好的依赖。编译 Android App 另需 Android SDK、JDK 和 Gradle，见[Android 说明](android/README.md)。

1. 双击项目根目录的 [start-local.cmd](start-local.cmd)，启动电脑网页和手机局域网入口。首次缺少数据库时会创建空库，并交互式设置至少 6 个字符的 `admin` 密码；已有数据库不会被初始化覆盖，也不会自动导入样例模具。
2. 电脑浏览器打开 `http://127.0.0.1:5173/`。由维护员建立真实人员、账号、位置及模具资料，或使用 CSV 导入。
3. 手机安装 [debug APK](android/app/build/outputs/apk/debug/app-debug.apk)，在 App 设置填写 `http://电脑IP:5174`；手机和电脑需在可互访的局域网中。登录个人账号后登记设备，由维护员在电脑端授权，再刷新设备状态进行作业。
4. 结束时双击 [stop-local.cmd](stop-local.cmd) 关闭并备份，再安全弹出 U 盘。电脑重启后需再次启动服务。

当前测试版使用 **HTTP 5174，无需额外安装 CA 证书**，原生 App 相机扫码仍可使用。手机网页地址为 `http://电脑IP:5174/?view=mobile`；HTTP 下可拍照识别二维码，浏览器实时相机需要可信 HTTPS。

HTTPS 5175 和 CA 脚本保留为可选验证方案，不参与日常默认启动，也未将测试电脑的 CA 打包进 APK。HTTP 仅用于可信局域网测试；正式版仍要求 HTTPS，证书、固定地址、发布签名和分发方式待正式部署时确定。

启动失败时先查看启动窗口及 `%LOCALAPPDATA%\mold-warehouse-dev\logs` 日志；具体操作和故障处理见[办公室试点操作说明](办公室试点操作说明.md)。

## 数据保存与换电脑

当前项目和活动 SQLite 数据库一起放在 U 盘开发工作区。以后迁移时，先关闭服务并完成备份，再整体复制项目和 `office-pilot-data/warehouse.sqlite3`；不要在服务运行时拔盘或在两台电脑上同时打开同一数据库。依赖、日志和安全备份放在各电脑本地，不是另一份活动库存库。

新电脑需准备运行依赖并启动服务，手机 App 修改为新电脑的地址。迁移前先在原地址处理待确认请求；普通草稿清空后重新扫码，不能把旧地址的待确认单据直接发往新地址。跨电脑迁移和备份恢复尚需完整演练。

原 PostgreSQL/Compose 部署草案未按“整包移动同一 SQLite 库”的决定完成调整；正式模式仍沿用旧 PostgreSQL 配置校验，不能把当前测试启动方式当作已验收的正式部署。
